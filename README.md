# php8check - проверка сайта на 1С-Битрикс и MODX перед переходом на PHP 8

Хостинги отключают старые версии PHP, и сайт на 1С-Битрикс или MODX после переключения на PHP 8 может просто перестать открываться. Этот скрипт заранее показывает, что именно сломается.

Один файл, без установки и без Composer. Работает на том хостинге, где сайт живёт сейчас (PHP 5.4 и выше). Ничего не меняет на сайте и никуда не отправляет данные.

## Что проверяет

**Движок**
- 1С-Битрикс: версия главного модуля и поддерживает ли она нужную версию PHP. Если ядро старое, скрипт скажет, что сначала нужно обновить его.
- MODX: версия и совместимость с PHP 8.

**Окружение**
- версия MySQL: 1С-Битрикс с 01.09.2026 ограничила поддержку на MySQL ниже 8.0 (рекомендует 8.4 и выше). Скрипт только читает версию, ничего в базе не меняет;
- подключение к базе через удалённое расширение mysql (MysqlConnection, BX_USE_MYSQLI);
- mbstring.func_overload в настройках и в .htaccess;
- кодировка windows-1251.

**Код сайта** (ядро движка не трогает)
- 1С-Битрикс: /local, init.php и обработчики, шаблоны, свои и сторонние компоненты, сторонние модули из Маркетплейса, публичная часть;
- MODX: дополнения в core/components и assets/components, статичные элементы, а также сниппеты и плагины из базы.

Что ищет в коде:
- удалённые функции: each, create_function, mysql_*, ereg/split, mcrypt_*, money_format, get_magic_quotes_*, convert_cyr_string, __autoload и другие;
- синтаксис, из-за которого файл перестаёт работать целиком: `$str{0}`, `(real)`, `(unset)`;
- конструкторы в стиле PHP 4 (метод с именем класса);
- старый порядок аргументов `implode($array, ',')`;
- `define(..., ..., true)`;
- то, что даёт предупреждения на новых версиях:
  - 8.1: методы ArrayAccess, Iterator, Countable, JsonSerializable без типа возврата, Serializable без `__serialize()`, FILTER_SANITIZE_STRING, strftime;
  - 8.2: `"${var}"` в строках, utf8_encode/utf8_decode, кодировка HTML-ENTITIES в mb_*;
  - 8.3: get_class() без аргумента;
  - 8.4: неявный nullable-тип `Type $x = null` - встречается почти в каждом старом модуле;
  - 8.5: `(integer)`, `(boolean)`, `(double)`, обратные кавычки, curl_close, imagedestroy и т.п.

Код разбирается парсером PHP (token_get_all), а не поиском по тексту, поэтому комментарии и строки не дают ложных срабатываний. Если на сайте есть своя замена удалённой функции, скрипт это учтёт.

## Как пользоваться

### В браузере

1. Скачайте [php8check.php](php8check.php).
2. Переименуйте файл, добавив случайные символы: например, `php8check-k3m9x2q7p4r8.php`. Без этого скрипт не запустится: так посторонний не сможет открыть отчёт о вашем сайте.
3. Загрузите файл в корень сайта (рядом с папкой bitrix или с config.core.php для MODX).
4. Откройте его в браузере. Вверху можно выбрать версию PHP, под которую проверять: 8.2, 8.3, 8.4 или 8.5 (по умолчанию 8.2).
5. После проверки удалите файл - кнопкой внизу отчёта или вручную.

### В консоли

```
php php8check.php /путь/к/сайту 8.4
```

## Важно: это не панацея

- Скрипт читает код, но не запускает его, поэтому может ошибаться в обе стороны: пропустить проблему или показать то, что на деле не сломается.
- Он не видит ошибок, которые проявляются только во время работы: null в строковых функциях, динамические свойства объектов, несовпадение типов, особенности сторонних библиотек.
- Зашифрованные файлы (ionCube и подобные) проверить нельзя - их нужно обновлять у разработчика модуля.
- Данные о совместимости версий ядра с PHP - ориентир. Сверяйтесь с официальной информацией 1С-Битрикс и MODX.
- Окончательная проверка - только на тестовой копии сайта с новой версией PHP: каталог, корзина, оформление заказа, формы, личный кабинет, админка, обмены.
- Скрипт ничего не меняет на сайте. Используете его на свой риск.

## Как переходить безопасно

1С-Битрикс с 01.02.2026 ограничила поддержку продуктов на PHP ниже 8.2 и рекомендует PHP 8.4 и выше. Порядок, который она советует: сначала MySQL, затем обновление продукта, затем PHP.

1. Полная копия сайта и базы.
2. Тестовая копия на поддомене с новой версией PHP.
3. Обновление ядра и сторонних модулей, исправление найденного.
4. Проверка ключевых сценариев и лога ошибок PHP.
5. Только потом - переключение рабочего сайта.

Не хотите разбираться сами? Переведу сайт на PHP 8 на тестовой копии, без риска для рабочего сайта: [заказать на Kwork](https://kwork.ru/website-repair/55321956/perevedu-sayt-na-php-8-bez-polomok-s-proverkoy-na-testovoy-kopii).
